---
title: 调整唤醒行为
description: 用 standard、v3、jev 三种引擎控制「要不要理这条消息」
---

唤醒引擎（wakeup engine）在每条消息上回答一个问题：这条消息要不要唤醒 bot。本文按场景给出三种引擎的配置方法。

配置位置：profile 的 `wakeup` 段。缺省引擎为 `standard`。换引擎只改 `engine` 字段，其余段与上下文、工具调用引擎互相独立、可任意混搭。

## 三种引擎的常用配置

按场景对号入座，下面给出三种引擎最常被采用的配置形态。

<Tabs groupId="wakeup-engine" items={['standard｜关键词触发', 'v3｜响应意愿', 'jev｜模型判定']}>
<Tab value="standard｜关键词触发">

### 固定规则，零额外开销

standard 引擎按固定规则判定，不消耗额外模型调用：

```yaml
wakeup:
  engine: standard
  standard:
    direct: true          # 私聊必醒
    atSelf: true          # 被 @ 必醒
    quoteSelf: true       # 引用回复 bot 的消息必醒
    keywords:             # 消息包含任一关键词必醒
      - neko
      - 喵酱
```

四条规则独立生效，命中任一即唤醒。全部关掉（四项全 false/空）意味着 bot 只会「听」不会「醒」，消息仍会进入上下文但不触发回复——可以用来做纯观察者。

默认值：`direct`、`atSelf`、`quoteSelf` 均为 `true`，`keywords` 为空。

</Tab>
<Tab value="v3｜响应意愿">

### 意愿值：多数时候沉默，偶尔自然插话

v3 引擎为每个频道维护一个「意愿值」：被 @ 、私聊等事件加分，被打扰后衰减，意愿越高越可能开口。适合「多数时间沉默、偶尔自然插话」的群聊人格：

```yaml
wakeup:
  engine: v3
  v3:
    base: 12                      # 一条普通消息的基础分
    atMention: 100                # 被 @ 的加成
    isQuote: 15                   # 引用 bot 消息的加成
    isDirectMessage: 40           # 私聊的加成
    keywords: [neko, 喵酱]        # 命中任一即改用 keywordMultiplier
    keywordMultiplier: 1.2
    defaultMultiplier: 1
    maxWillingness: 100           # 意愿上限
    decayHalfLifeSeconds: 600     # 无打扰时的衰减半衰期（秒）
    probabilityThreshold: 55      # 意愿超过此值才有概率开口
    probabilityAmplifier: 0.04    # 超出阈值部分换算成开口概率的系数
    replyCost: 35                 # 每开口一轮扣掉的意愿
```

调节思路：

- **太话痨** → 调高 `probabilityThreshold` 或 `replyCost`；调低 `base`。
- **太沉默** → 反向调节，或调低 `decayHalfLifeSeconds` 让热情维持更久。
- `keywords` 命中不是「必醒」，而是乘上 `keywordMultiplier`，所以话题相关时更容易被唤醒。

channel 模式下每个频道独立计分，群聊和私聊天然分开，不需要拆 profile。

</Tab>

### 让模型自己判断此刻该不该开口

jev 引擎把「要不要说话」交给一次轻量模型调用。它按三个维度各问一句——是不是在跟 bot 说话（addressed）、bot 对这个话题有没有话说（interested）、是不是别人之间的对话（others）——合成为 0 到 1 的量，超过阈值才开口：

```yaml
wakeup:
  engine: jev
  jev:
    apiKey: ${TYPESAFE_API_KEY}   # 或环境变量 TYPESAFE_API_KEY
    model: jev-latest             # 判定模型，走 typesafe-ai 方言
    threshold: 0.5                # 合成量的开口下限
    cooldownMs: 30000             # 上次开口后的静默期（毫秒）
    historyMessages: 8            # 每次判定喂给模型的最近消息条数
    timeoutMs: 1500               # 判定超时（毫秒），超时按不唤醒处理
    instruction: |                # 判定的补充约束（语气、何时闭嘴）
      neko，猫娘，话不多但会接梗。
      只在有人点名、话题与自己在做的工作有关、或有人明显在征求意见时插话；
      几个人互相寒暄时保持安静。
    interests:                    # 「感兴趣的话题」，只影响 interested 维度
      - LLM 工程与调试
      - TypeScript
    rules:                        # 兜底规则：命中即醒，不问模型
      direct: true
      atSelf: true
      quoteSelf: false
      keywords: []
```

要点：

- `threshold: 0.5` 是「毫无证据也开口」的临界值——三个维度都给 0.5 时合成恰好 0.5。调高它收紧的是合成量。
- `interests` 决定「bot 对什么话题有话说」，是 interested 维度唯一的信息来源；留空则该维度不偏袒任何话题。
- 兜底 `rules` 的结构就是 standard 引擎那四项，只写在 `jev` 段内部。

<Callout type="warn" title="前置条件">
需要 `apiKey`（或环境变量 `TYPESAFE_API_KEY`），且 `models.yaml` 中存在可用的 `typesafe-ai` 方言 provider。两者缺其一时，这份 profile 会在装载时被跳过。
</Callout>

<Callout type="warn">
每条未兜底命中的消息都会产生一次判定调用，高频群会带来持续的 API 消耗与延迟（默认上限 1.5 秒）。
</Callout>

## 验证与排错

换引擎后重启生效。验证 standard/jev 的兜底规则：私聊发一条消息应立即唤醒。验证 v3：连续普通消息后观察意愿爬升（开启 debug 日志可见）。

常见问题：

- **profile 被跳过，日志 `wakeup engine "jev" needs an apiKey`** → 补密钥或环境变量。
- **jev 判定永远不醒** → 检查 `timeoutMs` 是否过短、判定模型接口是否可用；`threshold` 是否设得过高。
- **rules 写成 `jev` 的同级段不生效** → 兜底规则必须在 `jev:` 段内部。
