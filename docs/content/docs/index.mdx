---
title: Ishiki 是什么
description: 用于构建自主 Agent 的 Bot 开发元框架
---

**Ishiki（意识）** 是用于构建自主 Agent 的 Bot 开发元框架。名称取自日语「意識（いしき）」。

> 意识的运行时，人格的栖息地。

它把上下文组织、模型交互与运行节律抽象为三个可替换的引擎族，并在三者之上提供工具编程、按需发现、统一资源访问与多实例运行。`koishi-plugin-ishiki` 是当前基于 Koishi 的核心运行时。

## 分层

| 层 | 承担的事 |
| --- | --- |
| `@yesimagent/core` | Agent 轮次、事实日志、插件钩子、工具与消息类型 |
| `@yesimagent/gateway` | `models.yaml`、供应商接入、模型组与候选排序 |
| `koishi-plugin-ishiki` | profile 与 runtime 装配、引擎选择、扩展装配、资源中心、Koishi 接入 |

`yesimagent` 提供轻量、可扩展的 Agent 运行时。Ishiki 在它的插件接口上定义了一份扩展契约，再补上角色运行需要的配置、寻址与资源管理。

## 三个引擎族

| 引擎族 | 回答的问题 | 内置变体 |
| --- | --- | --- |
| 上下文（context） | 本轮向模型提供哪些输入 | standard、v3 |
| 唤醒（wakeup） | Agent 何时运行、如何安排节律 | standard、v3、jev |
| 工具调用（toolcall） | 模型交互如何组织、如何产生工具调用 | native、v3、hermes、qwen3coder、morph-xml、yaml-xml |

同一个 runtime 在每一族里选择一个变体。上下文引擎检索与组织信息，形成模型输入；工具调用引擎通过 `LanguageModelV4` 中间件定义交互流程；唤醒引擎自行安排运行时机，可以基于事件判断，也可以在没有外部输入时持续调度。

三个关注点可以分别定制，具体变体按各自的接口约定配合工作。

每个变体是一个 Koishi 服务，按 `ishiki.engine.<族>.<名字>` 注册。第三方实现作为普通 Koishi 插件安装后按服务名被发现，profile 写名字即可选用；profile 引用了尚未安装的引擎时，这个 profile 停在等待态，依赖装好后再装配。

`narrative` 是独立插件提供的配套变体：上下文引擎维护可恢复的叙事，工具调用引擎在同一个模型调用内组织 Narrator、Action Decoder 与 Replyer。Narrator 推进叙事并选择下一步，Action Decoder 与 Replyer 是两条分支，分别产生工具调用与面向用户的回复。工具执行与会话存储仍由宿主负责。

## 工具与资源

- 内置工具包括 `read`、`send_message`、`finish` 与 `wait`。模型的普通文本默认只写入事实日志；要让消息到达平台，需要调用 `send_message`。
- `codemode` 默认关闭。开启后，多数业务工具收进 QuickJS，由模型写程序组合调用；`finish` 与 `wait` 保持直调，`send_message` 在直调与程序两侧都可用。
- `toolsearch` 默认关闭。开启后，非常驻工具延迟披露，`search` 命中的工具从下一步开始可调用。
- 每个 runtime 拥有独立的资源中心，内置 `asset`、`artifact`、`local` 三种方案。workspace、skill、mcp、onebot 等方案随对应扩展注册；`read` 接收完整 URL，交给对应方案解释。

## profile 与 runtime

- **profile** 是人格、激活与依赖隔离的单位。一份 `profile.yml` 声明模型、频道认领、三族引擎与 `extends` 扩展，`instructions` 引用存放人设的文件。
- **runtime** 是一个地址上的运行实例。channel 模式按频道各派生一份；cross 模式把认领的频道合流成一份，上下文跨频道共享。
- 上下文与唤醒实例、事实日志、资源目录按 runtime 独立；模型与工具调用包装按 profile 共享。
- runtime 按需创建：常见时机是第一条落到该地址的输入；创建后，后续输入与显式唤醒复用同一实例。

## 开始构建

当前使用源码构建，将核心运行时接入 Koishi。按[快速上手](/docs/tutorial/quickstart)配置模型与第一份 profile，即可开始运行。独立于 Koishi 的运行方式是项目的发展方向。
