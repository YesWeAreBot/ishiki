title: 快速上手
description: 从源码接入到第一个 Agent 的完整配置流程
---

完成这篇教程后，你会有一份已激活的 profile：它拥有自己的模型、人格和认领频道，可以通过 Koishi 接收消息、使用工具并发送回复。

## 准备环境

- 一个 **Koishi 4.18.11 或更高的 4.x 应用**，并且已经配置至少一个聊天平台适配器。
- **Node.js 20+** 与 **Bun**。
- 一个支持原生工具调用的模型接口及 API Key。本教程使用 OpenAI 兼容接口与默认 `native` 工具调用引擎。

以下使用 Bun 接入插件，假设 Koishi 应用目录 `koishi-app` 与 Ishiki 源码目录 `ishiki` 位于同一个父目录。

## 接入核心运行时

<Steps>
<Step>

### 构建源码

从两个目录的共同父目录开始执行：

```bash
git clone https://github.com/YesWeAreBot/ishiki.git
cd ishiki
bun install
bun run build
```

构建产物位于 `packages/koishi-plugin-ishiki/lib/`。本教程只需接入核心包；workspace、MCP、narrative 等扩展可以按需启用。

</Step>
<Step>

### 链接到 Koishi 应用

接着在当前 `ishiki` 目录执行：

```bash
cd packages/koishi-plugin-ishiki
bun link
cd ../../../koishi-app
bun link koishi-plugin-ishiki
```

相对路径按上述同级目录布局计算。如果应用位于其他位置，请将 `../../../koishi-app` 替换为应用目录。

在 Koishi 应用的 `koishi.yml` 中启用插件：

```yaml
plugins:
  ishiki: {}
```

</Step>
<Step>

### 配置模型

在 Koishi 应用中创建 `data/ishiki/models.yaml`：

```yaml
providers:
  my-api:
    api: openai-completions
    baseUrl: https://api.example.com/v1
    apiKey: YOUR_API_KEY
    models:
      - id: your-model-name
        input: [text]
        contextWindow: 128000
        maxTokens: 8192
```

替换 `baseUrl`、`apiKey` 和模型 `id`，并按模型能力填写上下文窗口与输出上限。`my-api` 是自定义供应商名称，profile 通过 `my-api:your-model-name` 引用这个模型。

`data/ishiki` 是默认数据目录，可以在插件的 `dataPath` 配置中修改。其他接口方言与模型组见[接入模型供应商](/docs/guides/models)。

<Callout type="warn" title="保存好模型凭据">
API Key 以明文保存在文件中。请限制文件访问权限，避免将数据目录提交到版本库。
</Callout>

</Step>
<Step>

### 创建 profile

创建 `data/ishiki/profiles/my-first/profile.yml`：

```yaml
model: my-api:your-model-name
mode: channel

channels:
  "onebot:BOT_ID":
    - "CHANNEL_ID"
```

将 `onebot:BOT_ID` 替换为机器人账号的 `platform:selfId`，将 `CHANNEL_ID` 替换为实际频道标识。这里的 `onebot` 对应 OneBot 适配器；使用其他平台时，填写该适配器的 platform。

每份 profile 是一份稳定人格的配置，`channels` 声明它接管的账号与频道。`"*"` 可以认领该账号的全部频道，`"!CHANNEL_ID"` 可以排除指定频道，完整规则见[编写 profile](/docs/guides/profile)。

本例使用默认引擎：`context.engine: standard`、`wakeup.engine: standard`、`toolcall.engine: native`。`channel` 模式为各频道分别创建 runtime。

</Step>
<Step>

### 写下人格

创建同目录下的 `persona.md`：

```markdown
你是小雪。表达清晰，保留自己的判断与好奇心。
记住正在推进的事情，使用工具完成能够执行的任务；
需要向对方表达时，直接说明结果。
```

人格会进入系统提示词。同一 profile 派生的 runtime 使用同一份人格声明。

</Step>
<Step>

### 启动并发送消息

启动 Koishi。日志中应出现：

```text
profile "my-first" activated: mode=channel, accounts=1
```

在已认领的频道中 @ 机器人，或引用它的消息。已认领的私聊也会命中默认唤醒规则。第一次输入路由到该频道时，会创建 runtime，日志包含：

```text
[my-first] runtime created: my-first/onebot:BOT_ID/CHANNEL_ID
```

Agent 运行后，通过 `send_message` 将可见消息发送到平台。若没有收到回复，检查本页的故障排查表。

</Step>
</Steps>

## 检查配置与实例数据

运行前的目录包含：

```files
data/ishiki
├── models.yaml
└── profiles
    └── my-first
        ├── profile.yml
        └── persona.md
```

runtime 创建后，profile 下会生成 `runtimes/`，保存实例的会话日志和资源。修改模型、profile 或人格文件后，需要重新加载插件；更新源码后，需要重新执行 `bun run build`。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Model config file not found` | 指定数据目录没有模型配置 | 创建或填写 `models.yaml`，重新加载插件 |
| `missing required service`，profile 等待 | 引擎或扩展服务缺失 | 核对名称，安装并启用对应 Koishi 插件 |
| profile 因认领冲突被跳过 | 多份 profile 接管了相同账号和频道 | 用 `!` 排除重叠频道，或调整认领范围 |
| `claims no accounts` | `channels` 缺失或为空 | 声明至少一个账号及其频道名单 |
| profile 已激活，输入没有触发运行 | 频道未被认领，或未命中唤醒条件 | 核对 `platform:selfId` 与频道标识，在认领频道中 @ 机器人 |
| 模型请求失败 | 接口配置有误或模型不支持所需能力 | 核对接口方言、地址、凭据、模型名称与工具调用支持情况 |

请求记录与详细日志的使用方法见[调试与排障](/docs/guides/debugging)。
