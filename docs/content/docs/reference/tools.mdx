## 内置工具

### send_message

发送可见消息，**模型对用户说话的唯一通道**。

<TypeTable
  type={{
    messages: {
      type: 'string[]',
      description: '要发送的消息（≥1 项），按序发送，条间按打字延迟等待',
      required: true,
    },
    mode: {
      type: '"element" | "raw"',
      default: 'raw',
      description: 'element：按消息元素解析（可含 <img/>、<at/> 等）；raw 或省略：纯文本',
    },
    continue: {
      type: 'boolean',
      default: 'false',
      description: 'true 时发送失败仍继续处理后续消息，并允许后续模型步骤；默认在失败时返回错误，发送成功后结束本轮',
    },
    target: {
      type: '{ sid, channelId }',
      description: '目标频道坐标，cross 模式必填，从频道事实块头部原样复制',
    },
  }}
/>

输出：成功 `{ ok: true, ids: string[] }`；失败 `{ ok: false, error: { name, message }, sent, failedAt }`（`failedAt` 是第几条失败的，从 0 计）。

行为要点：

- 消息里的媒体 `src` 支持 `asset://`、`artifact://`、`local://`、`workspace://`，解析为内联数据发送；解析失败的媒体被剔除并报告，不阻塞消息。
- cross 模式必须带 `target`，且目标必须在 profile 认领范围内。
- 打字延迟按 `typing` 配置逐条计算（中文按 `charPerSecond`、拉丁按其 1.5 倍，带抖动）。
- 模型直接调用 `send_message` 成功且未设置 `continue: true` 时，本轮结束；显式调用 `finish` 或 `wait` 也会结束本轮。

### read

读取资源，输入 `{ url }`。文件型 URL 支持行范围和元数据视图：

```text
read({ url: "artifact://bash/output.txt:1-200" })
read({ url: "asset://<32位十六进制>" })
read({ url: "workspace:///home/workspace/report.txt" })
read({ url: "local://notes.txt?view=meta" })
```

原始返回值是可序列化的判别联合：

| type | 内容 |
| --- | --- |
| `text` | `{ type, url, text, size, mediaType?, filename?, source? }`；`text` 包含请求范围内的完整内容 |
| `file` | `{ type, url, mediaType, data, byteLength, filename?, immutable }`；`data` 是 base64 媒体数据 |

- FileScheme 的行选择器为 `:N`、`:start-end` 或 `:start+count`，位于 query 之前。`?view=meta` 读取元数据，惰性 asset 不因此下载。
- FileScheme 文本的 `source` 包含 `{ url, offset, line, column }`，记录来源与位置；正文不混入展示尾注。
- codemode 内取得完整结果，不受模型展示预算截断；仍受 SDK 的传输、结果大小和执行限制约束。
- 传给其他工具时按其输入契约取 `result.text` 或 `result.data`；只有明确支持该 scheme 的工具才能直接接收资源 URL。最终的 `attachments` 可携带媒体节点。
- 模型可见的文件页使用原来源续读；普通 handler 返回的超长内容先固化为 artifact。按结果里的完整 Continue URL 再 read，即可继续读取，包括超长单行的剩余部分。其他 scheme 自行解释完整 URL，不继承文件语法。

### wait

声明下一次自动醒来的条件。它与 `finish`、`send_message` 同属**收尾动作**：调用它即结束当前轮次（和 `send_message` 一起调用时同样结束，模型不必为声明条件多跑一步）。常驻工具，只留模型目录，不受 codemode 的 `direct` 名单影响，也不进沙箱。

<TypeTable
  type={{
    msgs: {
      type: 'number',
      description: '再积累 N 条新入站消息后醒来',
    },
    secs: {
      type: 'number',
      description: 'T 秒后醒来，与有无输入无关（≥1）',
    },
  }}
/>

两个窗口中先满足的条件生效，每轮采用最后一次调用的声明。条件在轮次结束时启用，触发一次后清除；返回值回显当前声明，空调用返回 `none: true`。条件保存在内存中，重启后清除。持续的调度策略可以由自定义唤醒引擎管理，显式 `wake` 也可以独立触发运行。完整语义见[调整唤醒行为](/docs/guides/wakeup)。

### codemode

启用后，模型可以编写 JS 程序，在 QuickJS 沙箱中组合调用业务工具。codemode 默认关闭，开关与配额见[插件与 profile 配置](/docs/reference/plugin-config)。

- 程序内 `await tools.name(input)` / `await tools["server_tool"](input)` 返回工具的原始 JSON 安全值。中间数据由程序处理，最终返回值进入后续模型上下文。
- `direct` 名单内的工具保留模型直接调用入口，其余业务工具由程序调用；`send_message` 同时支持直接与程序调用，`finish`、`wait` 保持直接调用。
- 传媒体出沙箱的唯一方式：返回值顶层带 `attachments` 数组，元素是媒体块（MCP 的 image/audio 块、read 的 file 节点、内嵌 MCP resource）。数组外的一切按普通 JSON 处理。
- 每次调用是一个独立程序；需要分步传递的数据放进返回值，下一步以观察形式看到。

### search（toolsearch 开启时）

按名称与描述关键词发现延迟池里的工具：输入 `{ query }`，输出 `{ tools: [{ name, description? }] }`。命中的工具**下一步**起可调用；每步结束时目录有变化则持久化一条目录更新。默认 `catalogMode: incremental` 只包含新增、变更或删除的工具，`catalogMode: replace` 则每次发完整快照。常驻工具（`finish`、`send_message`、`read`、`wait`、`codemode`、`search` 加 `resident` 名单）永远可见。

### finish

结束当前轮次：输入 `{ reason? }`，输出 `{ ok: true }`。收尾动作应由模型直调发起。

## 资源 URL 方案

| 方案 | 语法 | 内容 |
| --- | --- | --- |
| `asset` | `asset://<32位十六进制>` | 平台媒体，惰性拉取：首次访问才下载并落盘 |
| `artifact` | `artifact://<tool>/<name>` | 工具输出归档；沙箱内对应 `/home/.ishiki/artifacts/<tool>/<name>` |
| `local` | `local://<相对路径>` | 实例目录（runtime home）内的文件；不可越出实例目录 |
| `skill` | `skill://<技能名>/<路径>` | workspace 扩展注册；路径缺省为 `SKILL.md`；共用 FileScheme |
| `workspace` | `workspace:///绝对路径` | workspace 扩展注册；sandbox 下读取实际虚拟文件系统，含持久文件、临时文件与挂载点 |
| `mcp` | `mcp://<服务器>/<资源URI>` | mcp-client 扩展注册；内部 URI 连同 query、冒号与 fragment 原样透传 |
| `onebot` | `onebot://actions`、`onebot://actions/<动作名>` | onebot 扩展注册；前者是当前后端的分类索引，后者是单动作的参数与后端差异 |

每个 runtime 拥有独立资源中心，URL 在该中心已注册的 scheme 中解析。`asset` / `artifact` / `local` 是内置保留方案，表中其余方案由对应扩展提供。扩展可以注册 HTTP(S) 等新 handler，继续通过 `read` 访问资源。

FileScheme 自行解析行选择器、`?view=meta` 与续读 offset；资源中心只按 scheme 路由完整 URL。文件名中的字面冒号使用 `%3A`。native 后端的 workspace URL 使用实际宿主路径；Windows 可写为 `workspace:///d/work/report.txt`，盘符段的字面冒号也需编码为 `%3A`。

普通 URL 可以表示当前资源；`artifact` 表示已固化内容快照。原来源续读不承诺跨次读取一致性。

## 文本预算

模型可见的文本共用 **2000 行 / 30,000 个 UTF-16 code unit** 的预算，正文与所有续读说明一起计入。截断不拆开 Unicode 代理对，不丢弃单行余文。

Continue URL 中的 `offset` 是请求范围内已消费的 UTF-16 code unit 数；URL 保留原来的行范围和 view。继续读取时使用返回的完整 URL，以保留范围与精确续读位置。读到范围末尾后不再生成 Continue。

read 返回请求范围内的完整内容，传输与执行仍受现有 SDK 限制约束。

## 工具结果的统一出口

工具原生 `toModelOutput` 先转换结果，再由统一资源出口处理：

- 普通超长内容：完整表示归档为 `artifact`，模型看到前缀与续读 URL。归档包含媒体替换后的完整展示内容，不另外保存 execute 原始对象。
- FileScheme 文本：使用已有来源分页，不把读取页面重新归档。
- 媒体：固化新数据或复用已固化引用，替换为 `[attachment: <url>; <mediaType>; …]`，另写附件消息，下一 step 按能力与配额投影。实时文件引用作为历史附件时保存快照。
- codemode 内部工具：不执行这条模型出口链路；只有最终返回值进入处理，显式媒体字段为 `attachments`。
