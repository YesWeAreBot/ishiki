Ishiki 的全部持久数据在 `<dataPath>`（默认 `data/ishiki`）。本文按布局逐项说明，帮你回答「这个文件是什么、能不能删」。

```files
data/ishiki
├── models.yaml
├── .mcp.json
├── requests
├── skills
└── profiles
    └── <profile ID>
        ├── profile.yml
        ├── PERSONA.md
        ├── mcp.json
        ├── memory
        └── runtimes
            └── <实例 key>
                ├── events.jsonl
                ├── workspace
                ├── resources
                │   ├── assets
                │   └── artifacts
                └── archives
                    └── <时间>_<uuid>
```

## 你维护的部分

| 路径 | 说明 |
| --- | --- |
| `models.yaml` | 见[参考：models.yaml](/docs/reference/models-yaml)；全新数据目录第一次启动时释放可编辑的模型模板 |
| `profiles/default/` | 全新数据目录第一次启动时释放的预设 profile；替换账号、频道和模型占位值后即可运行 |
| `profiles/<ID>/profile.yml` | 见[参考：插件与 profile 配置](/docs/reference/plugin-config) |
| `profiles/<ID>/PERSONA.md` | `instructions` 的缺省文件；文件列表与顺序在 `profile.yml` 中声明 |
| `profiles/<ID>/mcp.json` | 存在时**整体替换** `.mcp.json` 基线，不是合并 |
| `profiles/<ID>/memory/*.md` | v3 上下文记忆块，frontmatter 格式见[管理上下文窗口](/docs/guides/context) |
| `skills/` 与 profile 内技能目录 | workspace 扩展的技能库，格式见[启用工作区](/docs/guides/workspace) |

## 自动生成的部分

### runtimes/ 实例目录

实例目录在 profile 装配时按需创建：`channel` 模式每个认领频道一个（key 为 `<ID>/<platform:selfId>/<频道号>`），`cross` 模式整个 profile 一个（key 为 `<ID>/main`）。删除某实例目录等于抹掉该频道的全部记忆与资源；profile 未激活时删除不会自动重建，下次该频道触发时重建空实例。

### events.jsonl

实例的完整事件流，每行一个 JSON 条目，含消息、回合事件与 Ishiki 自定义条目。它是实例记忆的**唯一事实源**：每轮请求的历史投影、上下文压缩都从它出发。持续追加，不要手工编辑；文件损坏（某行非法 JSON）会影响该实例的恢复。

条目的字段、各类条目的写入时机与排查命令见[会话存储格式](/docs/reference/session-format)。使用 `narrative` 引擎时流中还包含 `ishiki.narrative` 条目，也列在该页。

### resources/assets/

平台媒体（聊天里的图片、音频、视频和文件）。每项使用 UUID v7 标识；字节文件名为 `<uuid>.<实际扩展名>`，元数据文件名为 `<uuid>.metadata.json`。元数据记录原始 `src`、媒体类型、来源信息、创建时间、实际文件名与自动下载结果。符合条件的 HTTP 来源在入站时自动下载，默认上限 20 MiB；来源不符合条件、声明缺失、超限或请求失败时保留引用，后续显式读取仍可尝试下载，读取上限单独为 20 MiB。

`assets.cleanup.enabled` 默认关闭；开启后按 `retentionDays`（默认 30 天）和 `intervalMinutes`（默认 60 分钟）删除过期 asset 的字节文件与元数据。清理只处理 assets，工具 artifact 不受影响。

### resources/artifacts/

工具输出的归档：内容寻址命名（SHA-256 前 16 位 + `.bin`），旁有 `.json` 元数据。沙箱内以 `/home/.ishiki/artifacts/<tool>/<name>` 只读可见。早期版本的 `<hash>-<type><hash>.blob` 命名仍可通过元数据解析读取。

### archives/

执行 `ishiki.session.archive [runtimeId]` 并确认后，该实例的 `events.jsonl` 与 `resources/` 被移动到 `archives/<YYYYMMDD-HHmmss>_<uuid>/`。省略 `runtimeId` 时归档当前频道归属的会话；控制台或未归属频道需要显式指定。归档后会话不再出现在会话列表，`runtime.json` 与服务配置保留。运行中的实例需要先停止对应 Runtime 再归档。

### requests/

`dumpRequests: true` 时每次模型调用写一对 `<时间戳>-<序号>-request.json` 与 `-response.sse`。纯调试产物，可整目录删除。

## 权限与备份建议

- `.gitignore` 应排除整个 `data/`（含密钥的 `models.yaml` 与聊天数据都不该入库）。
- 备份「你维护的部分」即可恢复人格与配置；`runtimes/` 是运行态，体积增长快，按需取舍。
- 跨机迁移时保持相对布局（`profiles/`、`models.yaml`）不变，`dataPath` 可在插件配置里改。
