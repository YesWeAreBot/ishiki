`models.yaml` 位于 `<dataPath>/models.yaml`，由 `@yesimagent/gateway` 读取，定义 Ishiki 可用的全部模型。顶层只有 `providers` 与 `groups` 两个键，均为映射。格式支持 YAML（推荐）或 JSON。

## providers

`providers.<providerId>` 定义一个供应商：

<TypeTable
  type={{
    api: {
      type: '方言枚举',
      description: '请求协议，见下表',
      required: true,
    },
    baseUrl: {
      type: 'string',
      description: '接口基础地址，视方言而定',
    },
    apiKey: {
      type: 'string',
      description: '密钥；支持 ${ENV_VAR} 环境变量插值',
      required: true,
    },
    headers: {
      type: 'Record<string, string>',
      description: '附加请求头',
    },
    settings: {
      type: 'object',
      description: '传给 AI SDK provider 的默认调用参数',
    },
    models: {
      type: 'ModelConfig[]',
      description: '模型目录',
    },
  }}
/>

方言枚举（键即 `api` 取值）：

| 方言 | 协议 |
| --- | --- |
| `openai-completions` | OpenAI `/chat/completions` 兼容（DeepSeek/Kimi/GLM/Groq/SiliconFlow/llama.cpp 等） |
| `openai-responses` | OpenAI Responses API |
| `anthropic-messages` | Anthropic Messages API |
| `google-generative-ai` | Google Generative AI |
| `typesafe-ai` | Typesafe 平台 |

### models[].语言模型字段

<TypeTable
  type={{
    id: {
      type: 'string',
      description: '模型 ID，对应接口的 model 参数',
      required: true,
    },
    name: {
      type: 'string',
      description: '显示名',
    },
    reasoning: {
      type: 'boolean',
      description: '是否推理模型',
    },
    input: {
      type: '("text" | "image")[]',
      description: '声明输入模态；imageInput: true 的 profile 要求全部候选含 image',
    },
    contextWindow: {
      type: 'number',
      description: '上下文窗口（token）',
    },
    maxTokens: {
      type: 'number',
      description: '输出上限（token）',
    },
    thinking: {
      type: '{ mode: "effort", efforts: ThinkLevel[] }',
      description: '思考档位声明',
    },
  }}
/>

思考档位全集：`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。

模型目录还支持 `language/embedding/image/speech/transcription/reranking/decision` 等类型标记；Ishiki 的对话调用使用语言模型。jev 唤醒引擎的判定请求按其 `endpoint` 独立配置，见[调整唤醒行为](/docs/guides/wakeup)。

## groups

`groups.<groupId>` 把多个模型引用编成候选列表：

<TypeTable
  type={{
    strategy: {
      type: '"failover" | "round-robin" | "random"',
      description: '候选选择策略',
    },
    models: {
      type: 'string[]',
      description: '模型引用列表，格式 provider:model[:档位]',
      required: true,
    },
    circuitBreaker: {
      type: '{ failureThreshold, cooldownSeconds }',
      description: '熔断器，见下',
    },
  }}
/>

熔断器默认值：`failureThreshold: 3`、`cooldownSeconds: 60`。连续失败达到阈值的候选进入冷却，冷却期内被跳过。

<Callout>
组只负责候选顺序与熔断记账，不改变请求本身；profile 的 `failover` 段控制重试次数与触发条件，见[参考：插件与 profile 配置](/docs/reference/plugin-config)。
</Callout>

## 模型引用语法

出现在 profile `model`、组 `models` 成员里的引用：

```text
provider:model
provider:model:thinkLevel
groupId
```

解析规则：按 `:` 切分；仅当最后一段**精确等于**某个思考档位名时才视为档位，否则整串按模型 ID 处理（因此 `qwen3:32b` 这类 ID 正常解析）。

## 校验与错误

- 构造期校验失败抛 `GatewayError`，启动日志可见；常见原因是 `api` 拼写、必填字段缺失。
- 全新数据目录第一次启动时，插件释放包含占位供应商的 `models.yaml`。已有数据目录缺少该文件时会自动创建空文件；空文件等于「无可用模型」，首个引用它的 profile 装配失败。
- `${VAR}` 引用的环境变量在展开时求值，缺失会导致引用解析失败。

## 完整示例

以下示例中的密钥均为占位符，替换为真实值：

```yaml
providers:
  deepseek:
    api: openai-completions
    baseUrl: https://api.deepseek.com
    apiKey: ${DEEPSEEK_KEY}
    models:
      - id: deepseek-chat
        name: DeepSeek Chat
        reasoning: true
        input: [text, image]
        contextWindow: 128000
        maxTokens: 8192
        thinking:
          mode: effort
          efforts: [none, low, high, max]

  local:
    api: openai-completions
    baseUrl: http://127.0.0.1:8080/v1
    apiKey: none
    models:
      - id: qwen3-32b
        input: [text]
        contextWindow: 65536

groups:
  chat:
    strategy: failover
    models:
      - deepseek:deepseek-chat
      - local:qwen3-32b
    circuitBreaker:
      failureThreshold: 2
      cooldownSeconds: 60
```
