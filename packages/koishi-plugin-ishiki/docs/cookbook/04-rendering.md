# 04 · 事实与投影

## 事实

事实是事件进入 profile 后的中性、持久记录。它描述发生了什么，以及发生在哪个场景；不记录：

- 当前 focus；
- 是否生成 notification；
- 是否触发 turn；
- 已经渲染好的正文。

事实携带摄入时可确认的来源、发送者、频道、消息 ID、时间和必要的引用信息。名称是快照，不由全局实体表回查。

事实流是唯一长期来源。模型看到的帧、状态和工作区都是投影，不回写成第二份事实。

## 事件路径

```text
平台事件
  → 归一化为事实
  → 按 profile 白名单进入事实流
  → 结合 focus 与可达规则分类
  → 投影为模型可读的原生消息
```

平台特有的解析只发生在入口。进入事实流后，渲染、场景归属和通知判断使用统一语义。

未知事件类型采用 fail-closed：可以保存，但不进入模型上下文，直到存在明确的事实解释和渲染规则。

## 场景归属

每条事实天然属于自己的场景。assistant 与 tool 条目没有独立频道字段时，归属到它们在流中发生时的 focus。

投影从上一检查点的 focus 开始沿流读取：

- 进入当前 cursor 场景的事实，渲染为裸消息行；
- 其他场景的事实，只有满足可达规则时才渲染为 notification；
- focus 切换记录推进 cursor，并成为新的消息段头；
- 其他原生消息保持原有 role 与顺序。

因此，历史条目不会被当前 focus 追溯改写。

## 自己的消息

心智成功发出的每条消息作为普通事实落盘，使用与外部消息相同的场景和行格式。它进入对应场景的帧历史，也可被频道查看能力读取。

它不再通过特殊的“我说”文本回放，也不在当前工作区重复出现；当前 step 的发送行为由 assistant/tool 轨迹表达。

发送失败不生成自消息事实。平台没有返回消息 ID 时也不伪造事实。

## 工具轨迹

工具调用和结果是心智行为的一部分：

- 在当前工作区保持原顺序和配对；
- 在帧中作为完整轨迹保留；
- 不被 notification 包装；
- 不靠渲染层重新猜测成功或失败。

帧的机械剪枝可以限制外部历史，但不能破坏工具调用与结果的配对。

## 扩展边界

事件扩展需要说明三件事：

1. 事实属于哪个场景；
2. 事实如何渲染成一条中性消息；
3. 非 focus 时，什么条件允许它成为 notification。

扩展只负责提供事实语义和可达条件，不负责决定全局 focus、唤醒、包装或检查点。profile 统一判断唤醒，投影统一决定最终形态。

缺少渲染规则、可达判断或正文渲染失败时，跳过该事件的整组模型输出并记录原因；原始事实保留。这个隔离不适用于存储错误、检查点错误或核心生命周期错误。
