# 04 · 事实、投影与扩展

## 事实

事实是事件进入 profile 后的中性、持久记录。它描述发生了什么，以及发生在哪个场景；不记录：

- 是否唤醒心智；
- 是否来自别的场景；
- 是否成功送达；
- 已经渲染好的正文。

事实携带摄入时可确认的地址（身体与频道）、发送者、消息 ID、时间与必要的引用信息。地址就在事实自己的载荷上，所以"这条事实属于哪里"是读字段而不是逐类型的规则。名称是快照，不由全局实体表回查。

每条事实只写进一个场景的流：属于它的那个场景。跨场景的话不是"共享"，而是第二种事实——内生刺激（见 02）。

事实流是唯一长期来源。模型看到的近期记录是投影，不回写成第二份事实。

## 事件路径

```text
平台会话
  → 受体归一化为一条事实（平台差异只在这里出现）
  → 规则判断它属于哪个场景（不属于就丢弃）
  → 唤醒规则判断是否开始一轮
  → 唤醒：挂载场景，事实在回合开始时落盘
  → 不唤醒：事实直接落盘
  → 投影：这个场景尾部的事实成为消息行
```

内容以平台元素语法原样进入事实，需要读内容的判断（例如是否提及心智）读的就是这一段原文。

未知事件类型采用 fail-closed：可以保存，但不进入模型上下文，直到有渲染规则登记了它。

## 单事件映射（Transform）

每个事件类型有一条渲染规则：把载荷变成模型读到的多模态部件。

- 内置规则覆盖消息、撤回、自消息与内生刺激；
- 宿主可以用 `ctx.ishiki.registerTransform(type, transform)` 登记自己事件类型的规则；
- 部件用 AI SDK 的 content parts 表达，文本与图片走同一条路径；
- 只读穿透只取其中的文本（非文本部件写成 `[image]` 这样的占位），送进模型的近期记录保留完整部件。

渲染规则只回答一件事：这个类型怎么读。它不决定唤醒、不决定归属、不负责包装。

## 工具轨迹

工具调用和结果是心智行为的一部分：

- 在近期记录里保持原顺序和配对；
- 不被任何包装改写；
- 不靠渲染层重新猜测成功或失败。

## 自己的消息

心智成功发出的每条消息作为普通事实落盘，使用与外部消息相同的行格式，也会出现在之后的近期记录里。发送失败不生成自消息事实；平台没有返回消息 ID 时也不伪造事实。

## 扩展缝隙

宿主现在能扩展的是两处，接口在 `src/extension.ts`：

| 缝隙     | 注册方式                       | 作用                   |
| -------- | ------------------------------ | ---------------------- |
| 协议入站 | `registerReceptor`             | 把平台会话归一化成事实 |
| 单事件   | `registerTransform`            | 一种事件类型怎么读     |
| 跨场景   | `emitStimulus` / `peekHistory` | 投递纸条与只读读取     |

唤醒规则和 `maxMessages` 写在 profile 里。第二种唤醒策略或第二种投影出现时再加注册表。
