# 04 · 事实与投影

## 事实

事实是事件进入 profile 后的中性、持久记录。它描述发生了什么，以及发生在哪个场景；不记录：

- 当前 focus；
- 是否生成 notification；
- 是否触发 turn；
- 已经渲染好的正文。

事实携带摄入时可确认的地址（身体与频道）、发送者、消息 ID、时间和必要的引用信息。地址就在事实自己的载荷上，所以“这条事实属于哪里”是读字段而不是逐类型的规则。名称是快照，不由全局实体表回查。

同一条流里还有第二种记录：心智把场外事实复述成的 notification（见 02）。它不是外部事件，但共享同一条流、同一套地址和同一套投影规则。

事实流是唯一长期来源。模型看到的帧、状态和工作区都是投影，不回写成第二份事实。

## 事件路径

```text
平台事件
  → 按 profile 白名单过滤，归一化为一条事实
  → 落到它自己的场景里
  → 单独问一次：现在唤醒心智吗
  → 否，且它点到了心智，就复述成一条 notification 再问一次
  → 投影：本代场景的事实成为裸行
```

平台特有的解析只发生在入口，之后不再有平台分支。内容以平台元素语法原样进入事实，需要读内容的判断（例如是否提及心智）读的就是这一段原文。

未知事件类型采用 fail-closed：可以保存，但不进入模型上下文，直到存在明确的事实解释和渲染规则。

## 场景归属

每条事实天然属于自己的场景：地址写在载荷上，没有第二种判断。assistant 与 tool 条目没有地址，归属到它们写下时的场景。

投影只读一个场景，就是本代检查点声明的那一个：

- 地址等于它的自定义消息渲染为裸消息行，第一条带一个声明地址的头；
- 地址不等于它的，在这里不被读取，只出现在帧或频道查看里；
- assistant、tool 条目原样通过，并截断裸行的行流；
- 没有渲染规则的类型直接跳过。

焦点切换本身是一次换代，所以一代只读一个场景，历史条目不会被后来的位置追溯改写。

## 自己的消息

心智成功发出的每条消息作为普通事实落盘，使用与外部消息相同的场景和行格式。它进入对应场景的帧历史，也可被频道查看能力读取。

它不再通过特殊的“我说”文本回放，也不在当前工作区重复出现；当前 step 的发送行为由 assistant/tool 轨迹表达。

发送失败不生成自消息事实。平台没有返回消息 ID 时也不伪造事实。

## 工具轨迹

工具调用和结果是心智行为的一部分：

- 在当前工作区保持原顺序和配对；
- 在帧中作为完整轨迹保留；
- 不被 notification 包装；
- 不靠渲染层重新猜测成功或失败。

帧的机械剪枝可以限制外部历史，但不能破坏工具调用与结果的配对。

## 扩展边界

事件扩展只需要说明一件事：这个类型如何渲染成一条文本。场景归属不需要它声明，地址就在事实自己身上。

扩展不负责决定唤醒、包装或检查点。profile 统一判断唤醒，投影统一决定形态。声明了类型却没有给出渲染方式的类型不进入模型上下文，但事实照旧保存。

渲染缺失时跳过该事件的模型输出；这个隔离不适用于存储错误、检查点错误或核心生命周期错误。
