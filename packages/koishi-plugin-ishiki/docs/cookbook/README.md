# ishiki cookbook

`cookbook` 是 ishiki 的概念说明。它描述心智、场景、通知、上下文和事实如何协作，不展开源码结构、接口实现或测试细节。

## 核心模型

- 一个 profile 对应一个主心智和一条独立事实流。
- 一个场景由一具身体和一个频道组成；频道 ID 只在身体的命名空间内有意义。
- 白名单同时决定心智接管哪些身体、接收哪些频道，以及可以在哪些场景响应。
- 心智同一时刻只打开一个场景。这个场景是 `focus`；其他场景里点到心智的事实被复述为一条 `notification`，落在当下场景的事实流里。
- 可见性与唤醒分开判断：事实可以只保存、进入上下文但不唤醒，或同时进入上下文并唤醒。
- 上下文按信息变化速度分为稳定区、帧、状态和工作区。检查点只重建帧，不因状态变化释放工作区。
- 事实是中性的持久记录，不携带 focus、notification 或唤醒结果；它们在投影时才获得上下文中的形态。通知因此是一份独立记录，不是事实的另一种形态。

## v1 边界

- 跨场景事件统一称为 `notification`。
- 不引入独立的 state-delta 机制；因果变化由工具结果表达，环境快照进入状态段。
- 帧按场景分段，每条事实只在一个场景段里出现一次；notification 是一份记录，和别的事实一样落进它所在场景的那一段。
- 不依赖 LLM 摘要维持连续性；连续性由事实流、机械帧和检查点提供。
- 不把工具能力绑定到 focus；focus 只决定默认寻址和优先装载的场景历史。
