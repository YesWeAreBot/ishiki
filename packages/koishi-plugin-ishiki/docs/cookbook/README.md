# ishiki cookbook

`cookbook` 是 ishiki 的概念说明。它描述心智、场景、唤醒、上下文和事实如何协作，不展开源码结构、接口实现或测试细节。

| 文档                                 | 内容                                        |
| ------------------------------------ | ------------------------------------------- |
| [01-profile.md](./01-profile.md)     | Profile、场景、声明式配置、白名单与分发边界 |
| [02-attention.md](./02-attention.md) | 单场景心智、唤醒、本地声带与跨场景的两扇门  |
| [03-context.md](./03-context.md)     | 上下文分段、帧、状态、工作区、检查点与卸载  |
| [04-rendering.md](./04-rendering.md) | 事实、投影、渲染规则与五处扩展缝隙          |

## 核心模型

- 一个 profile 是一个心智，由一个目录自包含地声明，拥有自己的场景与事实流。
- 一个场景由一具身体和一个频道组成；频道 ID 只在身体的命名空间内有意义。
- 每个场景有自己的 agent、自己的事实流、自己的帧；场景之间不共享历史，只看得到两扇门：只读穿透与内生刺激。
- 一条事实只属于一个场景，地址写在事实自己的载荷上。
- 唤醒与保存分开判断：不唤醒的事实照样落盘，只是不挂载 agent、不调用模型。
- 上下文按信息变化速度分为稳定区、帧、状态和工作区；帧是单场景的近期窗口。
- 事实是中性的持久记录，不携带唤醒结果；它在投影时才获得上下文中的形态。
- 场景空闲后从内存卸载，事实流留在磁盘，下一次唤醒从同一位置继续。

## 与其他文档的关系

- `docs/01-…`、`docs/02-…`、`docs/03-…` 是这次重构的设计规约（决定"为什么这样做"）。
- `cookbook` 是重构后的概念说明（描述"现在是怎么运作的"）。
- 插件配置与运行说明见 [`../README.md`](../../README.md)。

## 边界

- 不引入独立的 state-delta 机制；因果变化由工具结果表达，环境快照进入状态段。
- 不依赖 LLM 摘要维持连续性；连续性由事实流、机械帧和检查点提供。
- 不把能力绑定到"当前窗口"这类隐式状态：能力按场景解析，工具自己知道自己站在哪里。
- 复合状态（好感度、成员画像等）推迟；不提前污染事实流。
