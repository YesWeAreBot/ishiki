# ishiki cookbook

`cookbook` 是 ishiki 的概念说明：心智、场景、唤醒、上下文、事实与引擎如何协作。它描述现在是怎么运作的，以及为什么是这样；不展开测试细节。

## 核心模型

- 一个 **profile** 是一个心智，也是一个人设与通信域，由一个目录自包含地声明；不同 profile 不共享历史。
- 一个 **scene** 是一份装配清单；匹配到的每个**频道**各起一个独立实例，有自己的事实流与模型前缀。同一个频道只归属一个 scene。
- 一条事实只属于一个场景，地址写在事实自己的载荷上；地址里的 `sid` 不透明，任何地方都不拆开它。
- 唤醒与保存分开判断：不唤醒的事实照样落盘，只是不挂载实例、不调用模型。
- 场景之间没有工具可用的通道。需要共享语境的场合由配置声明：profile 挂 `cross: true` + `claims`，被认领的频道共用一块视窗。
- 运行参数按**内置缺省 ← profile ← scene** 三层合并；一个环节只能有一个引擎，插件只做加法。
- 事实是中性持久记录，不携带唤醒结果；它在投影时才获得上下文中的形态，投影不回写。
- 实例按需创建，本阶段不做空闲驱逐；事实流留在磁盘上，进程重启后从同一份文件继续。

## 边界

- 不引入检查点状态机、帧换代与 `state_delta`；历史修剪只有压缩一条路径。
- 不把能力绑定到「当前窗口」这类隐式状态：能力按场景解析，工具自己知道自己站在哪里。
- 不提前引入只有一个实现的接口；第二种实现出现时再抽机制。
- 复合状态（好感度、成员画像等）推迟，不提前污染事实流。
