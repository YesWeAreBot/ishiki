# 03 · 三区与帧重建

> v1 已确认。前置：[02-attention.md](./02-attention.md)。

每次调用由三块拼成。格子里放什么没有封闭清单，原则是**变得越慢的越靠前**，好打前缀缓存。

```
稳定区  系统提示、人设、长期记忆、工具清单与指南、极少变的插件扩展
帧      检查点快照：处境、压缩后的近期、常变的扩展与记忆
工作区  本检查点之后只追加：新消息、工具轨迹、focus-change delta 等
```

一个 turn 内，稳定区和帧的字节不变。新增只追加在工作区尾部。

v1 不引入通用 state delta 服务；focus-change delta 是注意力切换记录，不在此非目标之内。

## 工作区怎么投影

不缓存渲染结果。每 step 按流上的 cursor 重折：起点是帧上的 focus，碰到 `change_focus` 换挡。不要用此刻的 logical focus 去重渲已经走过的条目。

投影在 ishiki 的 `transformMessages` 内完成：遍历事实、判断可见性、调用注册渲染器、添加 awareness 包装，输出原生 `AgentMessage[]`。不引入中间 render 类型，也不跨 hook 传递 cursor。详见 [04-rendering.md](./04-rendering.md)。

## 帧怎么来

连续性靠机械剪枝，不靠 LLM 摘要。重建时写下帧文本，之后每个 step 直接用这份文本，不再用第二套判定去重渲上一代。

- **本代未发生 focus change，因阈值 / 空闲重建：** 先取工作区尾部 N 个原始 `AgentMessage` 条目，再做机械剪枝。N 可配置，工具、awareness 等也在范围内；不按渲染后的 `ModelMessage` 数量计数。
- **本代发生过 focus change：** 整个工作区经机械剪枝后进入新帧，不按 N 条截尾。“完整保留”指轨迹范围，不指保留所有原文。保留起始 focus 和切换 delta，外层声明为“上一代轨迹”，不能将整段标成来自旧频道。
- 切换重建时，当前 focus 的近期历史仍按独立窗口现查，只查当前工作集，不翻归档。上一代轨迹不递归包含整个旧帧。
- 分支按本代是否发生过切换判断，而非仅比较最终 focus：A → B → A 仍完整保留轨迹；切换与阈值同时命中时也走切换分支。
- 上一代轨迹与当前 focus 近期历史允许重复，不做跨区去重；分别标注两段用途。

### 机械剪枝

- 一条原始消息渲染成多条 `ModelMessage`，不改变 N 的计数。
- 尾部范围内有工具结果、缺少对应调用时，按 tool call ID 向前补齐，允许最终条数超过 N。若补回的消息含多个工具调用，也保持相应调用 / 结果关系完整，不留下悬空调用。
- 移除旧 assistant 消息中的 reasoning parts，保留普通文本和工具调用。
- 移除历史中的多模态附件，保留对应文本内容。不改变原始 storage，也不影响当前工作区完整呈现新消息与附件。
- 所有工具结果统一按可配置长度截断：保留首尾，中间插入明确的截断标记。
- 不区分成功 / 失败，不检查业务 payload 的 `ok`、`isError` 等字段，不通过文本猜测。此规则替代此前“失败结果保留原文”的设想，本阶段不扩展 yesimagent 工具返回元数据。
- 接受短错误通常落在上限内、长错误也可能被截断的取舍。

LLM 摘要以后可以替换机械压缩内容，不是 v1 前提。具体预算配置与首尾长度分配在实现计划中落实。

完整轨迹移入帧不保证释放足够的总上下文容量。纯工作区 token 阈值不包含帧；剪枝后仍超模型窗口时明确报错，不额外裁减历史，不做二次压缩、自适应缩窗或自动重试。由用户调整窗口及截断配置；v1 不要求为此增加精确的 provider 窗口预检。

## 何时重建

三种触发，都只换帧。当前没有进行中的 turn 才执行；若正在跑，记下“该重建”，等本轮结束。

| 触发 | 条件 |
| --- | --- |
| 阈值 | 纯工作区 token（不含稳定区、不含帧） |
| 空闲 | 一段时间没有任何新消息 |
| 切换 focus | 本代发生过 focus change，当前 turn 结束时重建 |

## 保存与恢复

```text
生成新帧
  → 保存新检查点
  → 保存成功后，切换帧与工作区
```

保存失败则报错，不执行后面的替换和旧工作区释放，不增加自动重试或补偿机制。重启时恢复已有状态；只有无可恢复状态的首次启动才使用 profile 配置的初始 focus。

帧快照的文件布局、检查点字段及恢复步骤在实现计划中落实，不以清空旧工作区作为保存的前置步骤。
