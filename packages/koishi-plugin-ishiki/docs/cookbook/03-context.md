# 03 · 上下文、帧与检查点

## 四段上下文

模型上下文按变化速度分段：

```text
稳定区   人格、规则、工具说明、身体与频道清单
帧       检查点保存的场景历史
状态     当前时间等低熵实时快照
工作区   最近事实、notification、工具轨迹与当前行动
```

稳定区和帧应尽量稳定；状态只承载小而慢的变化；工作区承载需要保留因果顺序的新鲜信息。

这个划分服务于前缀缓存：变化只有三种路线，追加、局部替换、等检查点重建。信息越慢，越靠前；状态变化不应顺带释放工作区。

## 帧

帧是一次检查点物化的短期历史。它以当前 focus 场景开头，随后按场景分段：

- 进入帧的场景有两个来源：本代所在的场景，以及本代工作区里出现过的其他场景；
- 每个场景走同一条规则，从存储读取近期事实，按时间窗口过滤后取尾部若干条；
- 每个场景只有一个历史段；每条事实只出现一次，不因为它是通知还是外部消息而不同。

工具轨迹按调用发生时的 focus 归属。切换发生在 step 边界，因此切换前的整步轨迹留在旧场景，新代从新 focus 开始。

帧优先保留原文近史。机械裁剪可以限制存储路线的条数和时间范围，但不把 LLM 摘要当作 v1 连续性的必要条件。

## 状态

状态段位于帧和工作区之间，每次投影从权威状态重新生成，不落入事实流，也不进入检查点内容。

v1 只放低熵、低频变化的时间快照，并将时间量化为一天中的时间段。精确时间、情绪和其他每轮变化的字段属于工作区，不属于状态段。

状态变化只支付从状态段开始的前缀 miss；工作区可以继续复用。状态变化不是释放历史的理由。

## 工作区

工作区是检查点之后的 append-only 轨迹：新事实、notification、assistant/tool 轨迹和当前 step 的结果按流顺序追加。

- 本代场景内的事实渲染为连续消息行，第一条带一个声明场景的头；
- 其他场景的事实在这里根本不被读取；它们留在自己的场景里，或被复述成一条通知；
- assistant、tool 及其配对原样保留，并截断上面那条行流；
- 心智自己成功发送的消息进入帧历史，不在工作区再次作为外部事实出现。

投影不使用当前实时 focus 回头解释已经发生的旧条目：本代的场景由检查点决定，切换焦点会另起一代，所以一代只读一个场景。

## 检查点与释放

检查点保存一份帧文本和该代的 focus。成功保存后，旧工作区才成为已折叠历史；保存失败则保留原工作区。

检查点有三类触发：

1. focus 改变：在 step 边界立即换代；
2. 工作区超过预算；
3. 心智空闲足够久。

三类触发独立判断，同时发生时合并为一次检查点。状态变化单独更新状态段，不触发工作区释放。

如果 focus 切换时检查点写入失败，这次切换不发生：心智留在原场景，登记保留到下一个 step 边界重试。

## 连续性不变式

- 帧文本在同一代内冻结。
- 工作区代内只增不改。
- 每条事实只在一个场景段中出现一次。
- 工具调用与结果保持配对。
- notification 是一份独立记录，与它复述的事实各在自己的场景里，互不替代。
- 投影失败可以跳过单条事件，但不能吞掉事实保存或检查点保存失败。
