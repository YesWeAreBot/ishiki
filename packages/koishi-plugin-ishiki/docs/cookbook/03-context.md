# 03 · 三区与帧重建

> v1 已确认。前置：[02-attention.md](./02-attention.md)。

每次调用由三块拼成。格子里放什么没有封闭清单，原则是**变得越慢的越靠前**，好打前缀缓存。

```
稳定区  系统提示（人设 + 心智模式 + focus 语义 + 身体与频道清单）、极少变的插件扩展
帧      检查点快照：按场景分组的各段（当前窗口 + 这一代工作过的场景 + 只被叫到过的场景）
工作区  本检查点之后只追加：新消息、工具轨迹、focus-change delta 等
```

一个 turn 内，稳定区和帧的字节不变。新增只追加在工作区尾部。

v1 不引入通用 state delta 服务；focus-change 条目降级为 checkpoint 写失败时的保险丝，不再常规落盘。

## 工作区怎么投影

不缓存渲染结果。每 step 按流上的 cursor 重折：起点是帧上的 focus，碰到 `[focus change]` 换挡。不要用此刻的 logical focus 去重渲已经走过的条目。

工具的参数与返回值只写在工具 schema 里：稳定区再抄一份就会与 schema 漂移。稳定区讲"这个心智怎么运转"——一次唤醒是一个 turn、focus 是什么、有哪些身体与频道可发话。

投影在 ishiki 的 `transformEntries` 内完成：遍历事实、判断可见性、把当前焦点里的事件渲染成裸行、给别处够得着的事件加 awareness 包装，输出原生 `AgentMessage[]`。不引入中间 render 类型，也不跨 hook 传递 cursor。详见 [04-rendering.md](./04-rendering.md)。

## 位置从哪来

模型任何时候都该知道自己在哪，不必从块的形状去猜：

- **有检查点**：帧就是位置声明，`<frame at focus_sid focus_channel name>` 写在帧首。
- **没有检查点**（旧流、或开局帧写入失败）：投影按同一元素自行给出 `<frame …/>`，取值只用该代首条 entry 与配置里的 initial focus，所以同一 turn 的每个 step 渲染出完全相同的字符串。
- **全新 profile**：`start()` 在第一次 turn 之前先写一条开局帧，里面只有一句首代独有的事实（"在此之前没有发生过任何事"）。说的是**这段记录**，不是身体状态——写成"刚醒来"会被读成"它刚睡醒"，进而影响语气。选在第一次 turn 之前而不是首轮结束之后，是因为后者会改写已经发出去的前缀。

## 帧怎么来

连续性靠机械剪枝，不靠 LLM 摘要。重建时写下帧文本，之后每个 step 直接用这份文本，不再用第二套判定去重渲上一代。

- **焦点段：** 本代工作区里属于焦点场景的条目 + 本代的工具轨迹，按流序，**不做尾部截断**（受工作区预算 W 间接约束）。
- **其余场景：** 这一代工作过的场景（含刚被离开的那个）用它在工作区里的切片（事实 + 在那个场景里跑过的工具轨迹）；只被叫到过的场景从存储拉，取尾部 `context.historyEntries` 条、且只收 `context.sceneWindowMs` 以内的事实，被裁时写一行 `<!-- 更早 N 条已折叠 -->`。
- **工具轨迹的归属：** 按调用发生时的 cursor 归属。换代发生在 step 边界、工作区 cursor 不动，所以一次切换把整步的轨迹留给**被离开**的那个场景，新焦点段里不会有上一步的工具调用。
- 段序：焦点段最前，其余按最近活跃倒序。帧里没有 `last_focus_history`，也没有 `<scenes>`；帧内不出现 awareness / self 包装块。
- 每条事实只有一个归属场景，所以同一段话在帧里只出现一次。

### 机械剪枝

- 一条原始消息渲染成多条 `ModelMessage`，不改变 N 的计数。
- 帧侧不再有尾部截断，所以不存在“按 tool call ID 向前补齐”这条规则（`completeToolCalls` 已删除）：段内按流序渲染，调用与结果相邻。
- 移除旧 assistant 消息中的 reasoning parts，保留普通文本和工具调用。
- 移除历史中的多模态附件，保留对应文本内容。不改变原始 storage，也不影响当前工作区完整呈现新消息与附件。
- 工具参数与工具结果都**不截断**、不做中段裁剪：每个 tool-call 一行 `[工具调用] name: {完整参数}`，每个 tool-result 一行 `[工具结果] name: {完整结果}`（`truncateMiddle` 与 `context.toolResultChars` 已删除）。
- 不区分成功 / 失败，不检查业务 payload 的 `ok`、`isError` 等字段，不通过文本猜测。此规则替代此前“失败结果保留原文”的设想，本阶段不扩展 yesimagent 工具返回元数据。
- 代价是长输出会整段进帧，靠工作区预算 W 与存储路线的条数上限兜底。

LLM 摘要以后可以替换机械压缩内容，不是 v1 前提。具体预算配置与首尾长度分配在实现计划中落实。

完整轨迹移入帧不保证释放足够的总上下文容量。纯工作区 token 阈值不包含帧；剪枝后仍超模型窗口时明确报错，不额外裁减历史，不做二次压缩、自适应缩窗或自动重试。由用户调整窗口及截断配置；v1 不要求为此增加精确的 provider 窗口预检。

## 何时重建

三种触发，都只换帧。阈值与空闲要等没有进行中的 turn；切换不在此列——它在 **step 边界立即换代**，不等本轮结束。

| 触发       | 条件                                               |
| ---------- | -------------------------------------------------- |
| 阈值       | 纯工作区 token（不含稳定区、不含帧）               |
| 空闲       | 一段时间没有任何新消息                             |
| 切换 focus | switch 立即换代：step 边界写检查点，不等 turn 结束 |

## 保存与恢复

```text
生成新帧
  → 保存新检查点
  → 保存成功后，切换帧与工作区
```

保存失败则报错，不执行后面的替换和旧工作区释放，不增加自动重试或补偿机制。重启时恢复已有状态；只有无可恢复状态的首次启动才使用 profile 配置的初始 focus。

帧快照的文件布局、检查点字段及恢复步骤在实现计划中落实，不以清空旧工作区作为保存的前置步骤。
