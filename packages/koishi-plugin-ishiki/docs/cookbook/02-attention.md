# 02 · 主心智、focus 与 notification

## 主心智

一个 profile 是一条被事件激活的意识流。心智不是持续运行的服务，而是在需要时开始一轮 turn；一轮由若干 step 组成，直到它主动结束或没有继续动作。

心智的能力是全局的。focus 不是能力范围，而是默认寻址和优先装载历史的位置。

## Focus

心智同一时刻只打开一个场景。焦点场景中的可见事实以连续消息行进入工作区，不需要逐行重复场景地址。

切换 focus 表示准备持续关注另一个场景。切换发生在当前 step 完成后，并立即开始新的上下文代际：

- 本 step 已经发生的工具调用和结果仍属于切换前的场景。
- 新代的帧头声明新的 focus。
- 不把目标场景的整段近期历史临时灌入当前工作区。
- 后续省略目标参数的发送默认指向新的 focus。

如果只是跨场景回一句话，应直接显式指定目标，不必切换 focus。

## Notification

非 focus 场景的事实不会自动进入工作区。只有满足场景外可达条件的事实才生成 notification，例如私聊、提及心智或命中关键词。

Notification 是短消息：它说明谁在什么场景说了什么，但不附带该场景的完整上下文。它只存在于工作区，不进入帧的场景历史包装。

Notification 可以：

- 只进入上下文，不唤醒心智；
- 唤醒空闲心智；
- 在已有 turn 时加入后续 step。

被忽略的非 focus 事实仍可保存在事实流中，但不会留下“未处理通知”之类的持久状态。需要背景时，用只读的频道查看能力主动读取。

## 可见性与唤醒

可见性决定事实是否进入本次模型上下文；唤醒决定是否开始或加入一轮。两者独立：

| 可见 | 唤醒 | 结果 |
| --- | --- | --- |
| 否 | 否 | 只保存事实 |
| 是 | 否 | 进入工作区，等待后续一轮处理 |
| 否 | 是 | 唤醒心智处理已有上下文 |
| 是 | 是 | 展示事实并请求运行 |

事实本身不携带这些判断。判断依据来自 profile 策略、当前 focus 和事件的来源信息。

## 工具语义

- `send_message`：唯一的对外表达出口。省略目标时使用 focus，也可以显式发送到其他允许场景。
- `finish`：明确选择沉默并结束本轮。
- `switch_focus`：改变默认场景，并在 step 边界开始新的代际。
- `peek_channel`：读取其他场景的近期事实，不改变 focus，不产生新的场景历史。

单场景 profile 不需要暴露 focus、notification 或跨场景寻址概念。能力、提示和上下文形态应一起降级，不能只隐藏工具参数。
