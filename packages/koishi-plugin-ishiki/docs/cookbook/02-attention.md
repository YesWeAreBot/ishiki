# 02 · 主心智

> v1 已确认。前置：[01-profile.md](./01-profile.md)。帧重建见 [03-context.md](./03-context.md)。

一个 profile 一个意识流。它不属于任何频道，同一时刻只 **focus** 一个场景，对其余白名单频道保持 **awareness**。

## 存储与渲染

storage 摄入该 profile 白名单内的全部消息。条目格式一致，不打 awareness 标记。

模型必须能看出消息来自哪个频道。非 focus 的高优先级和当前 focus 的普通消息，差别只出现在渲染。

一条可见事实对应一组连续的 `ModelMessage`，支持多模态附件；不与相邻事实做 run-length 合并。插件扩展与投影见 [04-rendering.md](./04-rendering.md)。

- focus 消息不必携带 sid / scene，默认来源由帧的 focus 声明与流中的切换 delta 解释。
- 非 focus 消息使用正常正文，外层加 `<awareness scene="sid/channel">…</awareness>` 标明来源；正文不必重复地址。此处标签仅示意语义。
- 包装不改变多模态附件，文本正常渲染，附件保留在对应 content parts 中。

## Awareness

非 focus 的可见事件以 awareness 进入上下文，只渲染该事件，不附带该频道的额外上下文。可见不要求本次触发 turn。

内置消息的关注条件包括私聊、群聊 @、提及、引用、关键词。扩展事件通过注册的 `isVisible` 处理器决定是否可见；关注条件不等于必须触发。

awareness **可以起 turn**。已有 turn 在跑则 join，当作工作区追加，形态仍是 awareness。

触发引擎属于 profile，判断“主心智现在是否应该运行”，不把判定职责挂到单独的事件上。不把 `shouldTrigger` 或意愿分数写进消息 data；不在历史重渲时重复触发、累计意愿或随机判定。

## 触发评估与提交

触发策略与事件注册分离。事件注册负责事实类型、来源契约、可见性和正文渲染；profile 级策略可以结合多条消息、跨场景上下文与自身状态，不要求按事件类型逐一注册判定器。v1 不引入通用多策略仲裁机制。

引擎同时取得：

- **本次新增事实：** 待提交、尚未入库的消息或事件。
- **已有历史读取能力：** 此前已提交的记录，不包含本次新增事实；可以读取整个 profile 采集范围，包括不可见事件，不要求每次全量加载。
- **运行时状态：** 注意力、Agent 运行状态及策略所需的自身状态等。

不能只提供新增事实或只提供历史，也不能要求策略自行从全量历史猜测增量。具体参数、查询与状态接口在实现计划中确定。

```text
收到 / 构造新事件
  → 结合新增事实、已有历史与运行时状态评估
  → agent.send(事件, { trigger: 判定结果, ifBusy: … })
  → 返回 turnId，处理下一个事件
```

同一 profile 串行执行“评估 → send”。先评估、后由 `agent.send` 统一负责事件提交与触发，不先 append 再判断。

- `agent.send` 不等待 turn 结束；需要等待时用 `agent.wait`。摄入路径（session 监听器，turn 之外）可以 `await wait()` 来保证同一 profile 前一条处理完再提交下一条，但要知道它等待的是该 Agent 的**整个队列**；任何 turn 内部钩子（`onStepFinish` / `onTurnFinish` / 工具 `execute`）都不得 `await wait()`，否则自锁。
- 忙时按参数处理：`join` 追加到后续 step，`defer` 在当前 turn 结束后追加，`reject` 报错。常规 awareness 仍走既定 join 路径。
- 触发引擎当前只在新事件到达时评估，不新增定时检查或 turn 结束评估入口。帧重建的空闲触发不受此限制影响。
- 评估抛错时记录错误，仍调用 `agent.send`，使用 `trigger: false` 保留事实；busy 行为不变。
- 当前不设计 `send` 失败后的策略状态回滚、补偿或重试。

### v1 内置触发规则

只做 @ 自己、私聊、关键词触发，不实现复杂意愿累积、加权随机或语义判断。

- @ 自己：需要时解析 `content` 中的 at 元素，与自身身份匹配，不持久化派生布尔字段。
- 私聊：依据消息事实的 `kind: "private"`。
- 关键词：直接匹配消息的 `content`，包含配置关键词即命中，采用 `content.includes(keyword)` 的字面子串语义。不支持正则表达式；`.`、`*`、`[]` 等均为普通字符，也不要求先解析 elements 提取正文。

### 显式运行入口

事件入口由 core 评估是否唤醒；插件也可以拿到对应 profile 的 Agent，直接 `agent.send` 显式请求运行，跳过 ishiki 的触发策略。仍遵守 Agent 的 busy 机制，不另开循环，也不在事件 data 中增加 `forceTrigger`。显式触发不强制该事件可见。

## 可见性与触发独立

| 可见 | 触发 | 行为                                                    |
| ---- | ---- | ------------------------------------------------------- |
| 否   | 否   | 仅保存事实                                              |
| 是   | 否   | 进入可见工作区，不单独唤醒；后续 turn 可处理它          |
| 否   | 是   | 不展示本事件，但唤醒 Agent 处理已有上下文，例如插件心跳 |
| 是   | 是   | 展示事件，并请求运行                                    |

不能先按 `isVisible` 过滤，再让触发引擎只处理剩下的事件。触发路径在事件到达时执行，上下文路径在模型输入构造时执行；意愿未触发不能让原本可见的历史事件消失。

扩展处理器只返回是否可见，不返回 focus / awareness 分类，也不负责外层包装。`isVisible` 可以隐藏 focus 内的事件；“focus 全量可见”是内置消息的默认规则，不是绕过扩展处理器的强制规则。

`isVisible` 属于运行时注册定义，不是入库事件上的布尔字段。若判定依赖注意力，使用 core 提供的该事件位置上的历史 focus，而非当前 logical focus；重渲时遵守前缀稳定约定，不使用实时意愿或随机结果改变旧事件的可见性。

## 前缀与切 focus

`[instructions]` 和已渲染的 messages 前缀，只允许在帧重建时改。

本轮调用了 `change_focus` 到 B：

- 已经画出的形态保持不变。
- 追加 focus-change delta，说明此前默认来源是 A，此后默认来源是 B。之后新到的 B 消息按 focus 形态追加；A 的新消息仅在符合 awareness 条件时可见。
- 不把 B 的近期历史灌进本轮工作区。
- 需要选址的工具，缺省 target 变为 B。
- `change_focus` 默认不携带历史；模型显式指定条数时，将 B 最近 N 条消息放进**工具结果**。不直接追加成工作区历史消息。该条数与帧重建的近期历史窗口独立，具体参数名在实现计划中确定。

真正换帧在本轮结束之后，见 [03-context.md](./03-context.md)。

```text
focus = A
msgA
awareness[B]
focus-change A → B
msgB
awareness[A]
```

每次重渲仍按这条历史顺序解释来源，不用最终 focus 改写旧消息。
