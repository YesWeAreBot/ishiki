# 02 · 主心智、focus 与 notification

## 主心智

一个 profile 是一条被事件激活的意识流。心智不是持续运行的服务，而是在需要时开始一轮 turn；一轮由若干 step 组成，直到它主动结束或没有继续动作。

心智的能力是全局的。focus 不是能力范围，而是默认寻址和优先装载历史的位置。

## Focus

心智同一时刻只打开一个场景。焦点场景中的可见事实以连续消息行进入工作区，不需要逐行重复场景地址。

切换 focus 表示准备持续关注另一个场景。切换是一次原子动作：它以 step 边界上的新代际落地，落地之前心智仍在原场景。为了让整步留在同一个场景里：

- 本 step 已经发生的工具调用和结果仍属于切换前的场景，本 step 内的发送也仍寻址旧场景。
- 新代的帧头声明新的 focus。
- 不把目标场景的整段近期历史临时灌入当前工作区。
- 从下一个 step 起，省略目标参数的发送默认指向新的 focus。
- 同一个 step 里的第二次切换读到的是第一次登记的目标，所以“切过去再切回来”是一次真实的往返。
- 换代写不下去时，这次切换不发生，心智留在原地等下一个 step 边界重试。

如果只是跨场景回一句话，应直接显式指定目标，不必切换 focus。

## Notification

非 focus 场景的事实不进这份工作区。其中点到心智的那些（私聊、提及心智、引用心智、命中关键词）会被**复述**：另写一条 `notification` 记录，写明复述的理由和它复述的事实，地址取心智当下的场景。

复述的目的是让唤醒有话可说。一条场外事实本身不在当前场景里，直接唤醒心智会让它面对一段自己没有的上下文；复述把“别处发生了什么”搬到现在的位置。

复述是一条普通记录，因此：

- 它按自己的地址落进事实流，换代后进入帧的焦点段，也被焦点频道的查看能力读到；
- 它唤醒心智；
- 它不截断工作区的行流：它自带地址，读的人不需要额外的段头来回到当前场景。

被忽略的场外事实仍留在它自己的场景里，需要背景时用只读的频道查看能力主动读取。

## 可见性与唤醒

可见性决定事实是否进入本次模型上下文；唤醒决定是否开始或加入一轮。两者独立：

| 可见 | 唤醒 | 结果                           |
| ---- | ---- | ------------------------------ |
| 否   | 否   | 只保存事实，留在它自己的场景里 |
| 是   | 否   | 进入工作区，等待后续一轮处理   |
| 是   | 是   | 展示事实并请求运行             |

事实本身不携带这些判断。判断依据来自 profile 的策略、当前 focus 和事件自带的来源信息。

可见性与唤醒的四个组合里，“不可见却唤醒”当前没有产生它的路径：场外又点到心智的事实走的是复述，而复述本身是可见的。

## 工具语义

- `send_message`：唯一的对外表达出口。省略目标时使用 focus，也可以显式发送到其他允许场景。
- `finish`：明确选择沉默并结束本轮。
- `switch_focus`：改变默认场景，并在 step 边界开始新的代际；本 step 内它只登记这次移动。
- `peek_channel`：读取其他场景的近期事实，不改变 focus，不产生新的场景历史。

单场景 profile 不需要暴露 focus、notification 或跨场景寻址概念。能力、提示和上下文形态应一起降级，不能只隐藏工具参数。
