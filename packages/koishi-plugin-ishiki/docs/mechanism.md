## 1. 前缀缓存的不可能三角

前缀缓存按字节匹配。任何"每 turn 都可能变的信息"只有三条路,没有第四条:

| 路线         | 做法                  | 代价                                               |
| ------------ | --------------------- | -------------------------------------------------- |
| (a) 追加     | 变化作为新条目 append | 旧值残留,模型负责折叠(context rot、算术转嫁给模型) |
| (b) 原地替换 | 变了就改写那一段      | 该点之后所有字节重付(从该点 miss)                  |
| (c) 等检查点 | 冻结到帧重建          | 新鲜度 = 检查点节奏                                |

分流判据只有两个问题:**模型需要的是新鲜值还是变化轨迹?变了之后重付得起吗?**

v3 是全域 (b),v4 是 (a)+(c) 且拒绝 (b)。三区设计的真正价值不是"三块"本身,而是把信息按性质分流到不同路线。

## 2. 布局:四段

```
[稳定区]    persona / 规则 / 工具 schema
[帧·历史]   <memory> + <history>             ← 检查点节奏,冻结
[状态槽]    <state>当前时间(挂钟) / …        ← turn 节奏,重渲染
[工作区]    新消息、工具轨迹、awareness       ← append-only
```

信息路由表:

| 信息                        | 节奏                     | 归属                       |
| --------------------------- | ------------------------ | -------------------------- |
| persona、规则、工具 schema  | 不变                     | 稳定区                     |
| 关系、承诺、未决事项        | 慢、需综合               | 帧·memory(LLM)             |
| 对话近史                    | 慢、需原文质感           | 帧·hist(机械窗口)          |
| 粗时间、话题                | 每 turn 可能变、小、低熵 | 状态槽 (b)                 |
| 新消息、awareness、自致行为 | 事件驱动、需因果         | 工作区 (a)                 |
| 多样性 / 情绪 marker        | 每 turn、自包含          | 工作区 append(latest-wins) |

"变得越慢的越靠前"仍成立,但四段布局把它推进了一步:**历史段是缓存的经济单位(必须低频重算),状态部分是新鲜度的单位(应该高频),两者不能绑死在同一节奏上。**

## 3. 状态槽(state slot)

- **定义**:位于帧·历史与工作区之间的独立段,内容每轮从权威状态重新生成,不冻结、不参与折叠。
- **变更门控**:状态没变就不重渲染 → 字节不变 → 缓存从帧·历史起照常命中。
- **时间量化**:`14:32` 每 turn 必变(永远 miss);`下午` 一天变不了一次。粗档进槽,分钟级留在每条消息行的时间戳里(append 一次,无重付)。
- **时间取挂钟、带日期(09-19 定)**:槽的时间是**投影读时钟**——全文唯一一处。格式 `当前时间:2026年9月19日 凌晨`,4 档(凌晨 00–05 / 上午 06–11 / 下午 12–17 / 晚上 18–23)。代价:投影不再是流的纯函数,"同一条流两次投影逐字节相同"收窄为"除槽以外";换来的是语义正确(沉默很久后醒来,槽说的是现在,不是上一条消息的时间)与槽的输入收窄(不必先取流)。
- **注入点语义**:"像酒馆那样动态注入"走的就是 (b) 路线——槽即注入点;门控让静态注入零成本。
- **多样性回归**:v3 的"提示词常变 → 行为多样"在前缀层让渡给了缓存,但工作区尾部与状态槽是零缓存成本的变化插槽:每 turn 变化的提示词件放槽里(重付得起),或走 append 行(零重付、latest-wins)。

**护栏:槽必须小而低熵。** 槽里任何一个高频字段(未量化的时间、每轮都变的情绪 marker)都会把"50 token 的一次小 miss"变成"每轮重付整个工作区 W"。规则:槽里只放慢变量;热字段一律迁去工作区 append 行——**改的是字段去向,不是释放时机**。

- **在场者否决(09-19)**:焦点场景每一行都带名字,名单是那些行的纯派生;而它是槽里唯一随消息流量变化的字段——一个新面孔 = 从该字节到工作区末尾的全额重付。**槽只放慢变量**,所以它不进 v1(要做也应该走工作区 append 行,而不是槽)。

## 4. state delta 机制的收缩

原构想(所有影响上下文的操作追加 from→to 记录、检查点统计折叠)按信息性质二分后消解:

| 变化类型                                   | 机制                                      | 理由                                                               |
| ------------------------------------------ | ----------------------------------------- | ------------------------------------------------------------------ |
| 因果型(模型行为引起、需要看到变化才能推理) | 工具结果自述(`HP 20 → 4`),随工作区 append | 模型需要因果可见性;追加行即永久缓存                                |
| 环境型(时间、在线、情绪、频道元数据)       | 状态槽                                    | 需要的是新鲜值,不是变化轨迹;追加 `20→19→18` 是把折叠工作转嫁给模型 |
| 慢层综合(关系、承诺、未决)                 | 检查点 LLM 折叠                           | 压的是意义不是事件,才是 LLM 的增值区                               |

不再存在独立的 delta 追加机制。

## 5. 释放契约

释放管的是**轨迹**(hist / 工作区),只在检查点发生。三条触发器**各自独立判定**,同一边界撞上自然合并成一次检查点:

1. **槽变** → 只换槽,付一次小 miss,工作区原样沿用;
2. **帧变**(focus 切换) → 检查点 + 释放,强制(见 §9);
3. **W 超阈值 / 空闲够久** → 检查点 + 释放。

**"槽变 → 顺带释放工作区"明确否决**,论证存档:

- 前缀缓存是**最长公共前缀**,不是全有全无。槽变只失效槽字节起的一截、只此一轮;下一轮 `[稳定区][帧·历史][槽'][工作区A][新消息]` 中工作区 A 自动回到缓存——"逐字沿用"不需要任何操作,它就是免费的。
- 释放它 = 本轮多付一次折叠(含 LLM 调用)+ 不可逆保真损失,去换一笔本会自动回本的缓存债。
- 检查点之间的工作区是全系统唯一的**原文近史**;释放它 = 把"刚才逐字说了什么"换成有损折叠版,v3 病(每次重建都是有损投影)从后门回来。且"顺带释放"实质把代长缩短到"距上次状态变更"——状态变更越频繁,原文窗口越小。
- **判据:"保留 vs 释放"是 W 的函数,不是"是否发生过一次 miss"的函数。** miss 是这次变更的价格标签(付一次),不是重建的邀请函。

不动的部分:检查点概念(历史段必须低频重算)、工作区代内 append-only(代内任何修剪都是缓存自杀)、空闲重建(慢层落地后 = 把成本移出 turn)、存储真相 / 模型投影分离。

## 6. 帧·历史段解剖

帧按场景分组,每个活跃场景独立成段,段头自声明 sid/channel。

```
<frame at="..." focus_sid="..." focus_channel="...">
  <memory>      慢层:LLM 综合的承诺 / 关系 / 未决(预算内,"据回忆"性质)
  <history sid="..." channel="..." focus>
                焦点场景:工作区折叠,完整消息 + 机械剪枝
  <history sid="..." channel="...">
                非焦点场景 A:工作过的折工作区,其余从存储拉取
  ...           更多活跃的非焦点场景
</frame>
```

帧是唯一块头(`<frame ...>`);`<memory>` / `<history>` 是**区段**,不是块头——归属规则里的"块头 = 区段唯一开头"只作用于工作区投影与降级路径。

### 6.1 两种来源

- **这一代工作过的场景**(焦点,以及刚离开的旧焦点):帧内容来自**工作区折叠**——它这一代的事实行与工具轨迹,按流序。轨迹按**调用发生时的 cursor** 归属,所以一次换代把整步的轨迹留给被离开的那个场景,新焦点段里不会有上一步的工具调用。这是心智「刚才做了什么」的完整记录。
- **只被叫到过的场景**:帧内容来自**存储拉取**(尾部 `historyEntries` 条 + `sceneWindowMs` 时间窗口)。检查点时按场景从存储读取,不从工作区的 awareness 碎片拼凑,结果是连贯的对话段落,而不是散落在焦点历史缝隙里的包装块。心智自己在那里说过的话也在这里,因为它是那个场景的普通事实。

### 6.2 场景准入

**本代工作区里出现过的场景**进帧:出现过 awareness 事件(事实够得着),或心智自己在那里发过消息,或这一代的 cursor 在它那里(焦点与刚离开的那个场景)。一个都没占的场景不进帧,要看它的近况用 `peek_channel`。awareness 的双重角色:

- 运行时:注意力路由(什么事件进工作区);
- 检查点时:场景激活器(哪些非焦点场景在帧里获得独立 `<history>` 段落)。

帧内容的来源不是 awareness 本身——awareness 只提供准入信号,内容统一从存储读。

### 6.3 `last_focus_history` 取消

`last_focus_history` 的原始动机是桥接 focus 切换与帧重建之间的时间差。立即换代(§8)= 切换点就是检查点,时间差消失。旧焦点场景在新帧里有自己的一段:它是这一代真正工作过的场景(§6.1),所以那一段就是它在这一代里的切片——事实与工具轨迹都在,心智回去时既能看到上次聊到哪,也能看到上次在那里做过什么。

取消它省下的是**双源**:旧口径下同一个场景的内容会既在 `<history>` 又在 `<last_focus_history>` 里各印一次。现在每个场景恰好一段,重复问题结构性消失。

### 6.4 折叠策略

- **自己的话走普通事实通道(09-19 定)。** 模仿风险来自无限持久(v4 的 append 无界),一代的量有界;更硬的理由是对话完整性——hist 里留着"Alice: 你为什么这么说?"而没有我的话,模型面对无因之果,重复风险反而上升。落法:成功的 `send_message` 在落盘时写一条**普通消息事实**(带平台返回的 messageId 与自己的 user 快照),与别人的消息同类型、同渲染、同格式;发往别处的也不例外,它本来就是那个场景的事实,于是自动落在目标场景的段里。**转写特判整条删除**:不再有 `【我:内容】`、不再有 `<self>` 块、不再从调用参数里反推寻址与归属。可见性见 §7:进帧,不进工作区。备选否决存档反转:SelfMessage 事实原以"今天无第二消费者、参数/事实双源、新增落盘失败路径"被否决(YAGNI),09-19 翻案——删掉整条特判通道(跨场景归属、气泡逐项成行、失败路径、帧内去重)省下的复杂度大于双源那点重复,而事实通道让非焦点段恢复单一来源。
- **工具轨迹不折叠。** 工具参数与工具结果完整进帧,不做截断、不做中段裁剪;参数里有什么就呈现什么,`inner_thought` 也在其中,不做字段级裁剪。
- **先选择后综合。** 机械窗口是忠实裁剪(丢了什么可知),LLM 摘要是不可信压缩(会错、会丢错东西)。摘要只干慢层;把摘要当历史段主产品 = 拿最不可信的工具干最需要保真的活。
- **无信号场景不进帧。** 注意力过滤的产物就是遗忘;"看过没理"没有可操作的判定,任意的判据驱动持久标记会把过滤器变成任务队列。被提起时,"你怎么不理"本身就是恢复路径,peek 补状态。帧里不写任何未处理数或待回列表。

## 7. 主心智:焦点是装载,不是能力

- **能力全局**:发送能力显式寻址任何时刻可用;focus 只决定默认寻址 + 哪个场景的历史进缓存帧。
- **切换经济学**:持续投入一个场景 → switch(一次检查点,历史进帧摊销);顺路回一句 → 不切,显式寻址 + 必要时 peek。频繁横跳的病态用法本就该"不切而发"。
- **reach ⊇ wake**:起 turn 贵、进工作区可见便宜;叫醒你的事实必须可见,反之不必叫醒。
- **awareness 仅运行时(09-19 定)**:awareness 在工作区承担两个角色——注意力路由(什么事件进工作区)和场景激活器(哪些场景在下一帧获得自己的 `<history>` 段)。**帧内不再出现 awareness 包装块,也没有自述块。** 每一段的来源见 §6.1:这一代工作过的折工作区,只被叫到过的从存储读。
  - 工作区投影保持时序 + cursor + 包装块(运行时形态不变);帧渲染按场景分组、各段从各自来源构建(§6)。两套渲染逻辑各自简单。
  - **聚合取消(09-19 定)**:同场景连续命中不再合并成块。原聚合是帧侧 `renderEntries` 的 `pushFact` / `closeFacts`,帧内既然没有 awareness 包装块,它就没有消费方;把它搬进工作区投影,则要求每次追加都改写已发送的尾部块,与工作区代内 append-only(§5)冲突。工作区里一个事实一个块,连续命中就是连续的几个块。
- **自消息进帧不进工作区(09-19 定)。** 自己发出的消息落盘为普通事实,供帧渲染与 `peek_channel` 使用;工作区投影跳过它,工作区里「我说过什么」由工具调用记录承担。跳过只作用于工作区投影:帧侧折叠与存储拉取都照收。
- **帧内不重复(09-19 定,场景分组后自然满足)**:帧按场景分组(§6),每个场景的对话只在自己的 `<history>` 段出现一次;自消息是普通事实,同样只有一个归属场景。旧口径下的双源问题(同一段话既在 `<history>` 又在 `<last_focus_history>`)结构性消失——`last_focus_history` 已取消(§6.3),非焦点场景各有独立段落。
- **代内单切保留**:它是帧形状(单 prevFocus 槽)的自然结果;顺路需求由"不切而发"兜底;连切病态由帧级 miss 自限(§9),冷却从正确性约束降级为可选的成本护栏。

## 8. focus 切换立即重建

**决定:switch 采纳为"立即换代"——换代从 turn 边界提前到 step 边界,切换在语义和字节上同时完成。**

缓存账(换代 miss 总量守恒,时机只是搬家——turn 必然结束,帧 A 必然死于换代):

|                      | 推迟(turn 边界)      | 立即(step 边界) |
| -------------------- | -------------------- | --------------- |
| switch 后的收尾 step | [帧A][工作区] 全命中 | [帧B] miss      |
| 下 turn 首步         | [帧B] miss           | [帧B] 全命中    |
| 总 miss              | 帧 B ×1              | 帧 B ×1         |

立即重建的真实收益:

- **流内转换消失**:工作区不再出现 change 事件;switch 后的消息裸行在帧 B 之后的干净流里,归属 = 帧头,零状态跟踪、零歧义。
- **帧头永不过时**:不再是"帧说在 A、工作区说在 B"的过时声明。

落点:

- **时机 = step 边界**(pendingFocus 落盘点即重建点),不是工具 `execute` 内——那里本 step 的条目还没写完,重建会读到残缺工作区。
- **切换语义被 checkpoint 吸收**:`frameFocus + prevFocus` 已完整表达一次切换,成功路径不再落独立 change 条目。
- **change 条目降级为保险丝**:checkpoint 写失败时才落最小 change 标记;fold 的流内换挡逻辑保留作降级路径(见 §9)。
- **慢层延迟保护**:切换重建的 memory 段延用旧版文本,慢层异步重算、下一检查点替换——memory 是慢层,晚一代无妨;v1 机械剪枝无此问题。
- **重启恢复简化**:live focus = 最后 checkpoint 的 `frameFocus`,不再扫描流找 change 条目。

## 9. 归属规则:块头 = 区段唯一开头

立即重建后,归属歧义在 happy path 结构性消失;此规则约束**工作区投影**与**降级路径**(checkpoint 写失败、旧流):

- 每个场景区段都有显式开头;区段内裸行属于最近的开头;区段外的东西各有显式包装。模型的判定收敛为一条:**往前找最近的块头/包装**。
- 块头只允许三个来源:位置声明(帧 / `<frame/>`)、focus change(直接渲染成带 `from`/`reason` 属性的块头,不是旁白行)、夹断重开(awareness / 工具轨迹插进段中间后重开)。三者里只有位置声明出现在帧内;夹断重开与流内 change 属于工作区投影与降级路径。
- 帧按场景分组后(§6),帧内归属在 happy path 消失为问题:每个场景的段头自声明 sid/channel,段内裸行只属于该场景。此规则仍约束**工作区投影**(时序交织 + cursor + 块头)和降级路径(checkpoint 写失败时的流内 change 条目)。
- **每行场景短标记否决**:focus 行是消息大头,每行 +8~12 token 是持续成本;它消除的歧义块头已消除。仅当块头方案实际观察到误判时再升级。
