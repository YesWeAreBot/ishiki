# MCP 配置

两份文件，形状一样：

| 位置                                  | 作用                                                                |
| ------------------------------------- | ------------------------------------------------------------------- |
| `<dataPath>/.mcp.json`                | 基线。所有 profile 在自己没有文件时用它。                           |
| `<dataPath>/profiles/<名字>/mcp.json` | **完全替换**基线，不是叠加。写了它，该 profile 就看不到数据根那份。 |

形状由 [`mcp.schema.json`](./mcp.schema.json) 定义（JSON Schema draft 2020-12），
可填写样例见 [`mcp.example.json`](./mcp.example.json)。两份声明由测试对账，改了一边忘了另一边会跑红。

## 字段

判定分两种：**静态**的字段在装载时读一次，改完要重启 ishiki；**动态**的每轮现取或按次生效，
不用重启。

### 顶层

| 字段              | 语义                                                                           | 判定 |
| ----------------- | ------------------------------------------------------------------------------ | ---- |
| `mcpServers`      | 地图：服务器名到配置。名字会作工具名前缀，对外工具名是 `<服务器名>-<工具名>`。 | 静态 |
| `disabledServers` | 禁用名单：列在这里的一律不连，压过其余任何设置。                               | 静态 |
| `enabledServers`  | 启用白名单：强行打开列在这里的，压过 `enabled: false` 与禁用名单。             | 静态 |

### 每个服务器共有

| 字段           | 语义                                                                                                             | 判定                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------- |
| `enabled`      | 是否连这个服务器。`false` 表示完全不连（启用白名单除外）。缺省 `true`。                                          | 静态                   |
| `timeout`      | 单次工具调用的超时（毫秒），0 表示不限。不写则用 SDK 默认。握手（`initialize`）不受它影响，走 SDK 的默认 60 秒。 | **动态**，每次调用现取 |
| `instructions` | 该服务器 `getInstructions()` 自述的说明要不要进系统提示词。`false` 只关说明，工具照给。缺省 `true`。             | **动态**，每轮现算     |

### stdio（`type` 可省，缺省即 stdio）

| 字段      | 语义                                                                                                                                 | 判定 |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| `command` | 要拉起的可执行文件名。必填。                                                                                                         | 静态 |
| `args`    | 传给该进程的命令行参数。缺省 `[]`。                                                                                                  | 静态 |
| `env`     | 该进程的环境变量，值都是字符串。只覆盖列出的键，不继承父进程其余环境——SDK 的 `getDefaultEnvironment()` 给的是一份白名单。缺省 `{}`。 | 静态 |
| `cwd`     | 拉起进程时的工作目录；不写则继承当前目录。                                                                                           | 静态 |

### http / sse

`type` 必写（`http` 或 `sse`）。两者都要 `url`，可选 `headers`（值为字符串的对象）。

`http` 是 streamable HTTP；`sse` 是旧版传输，只为兼容仍在跑的服务器保留，新配置写 `http`。

## 坏配置怎么处理

两级校验，代价不同：

- **顶层形状不对**（`mcpServers` 不是对象、`disabledServers` 不是数组……）：整份文件丢弃，记一条 error，该 profile 零 MCP 工具。别人照常跑。
- **单个服务器形状不对**（缺 `command`、`type` 不认识、`timeout` 写了字符串）：只跳过这一个，记一条带服务器名的 error，其余照连。

任何一级都不往上抛——profile 层的异常会连带整个 profile 停摆，不该由一份配置文件触发。

## 工具结果里的图片

MCP 工具可以返回图片块。本包把字节直接交给模型（`ai` SDK 的 `content` 文件部件），
不落盘、不转文字。出口处有三道限额，超出的图片降级成一行说明：

- 单张 5 MiB
- 单次调用合计 10 MiB
- 单次调用最多 4 张

文本侧另有 30 000 字符上限。这些限额存在的原因是工具消息会被 `JSON.stringify` 后追加进
不可变事实流 `events.jsonl`，base64 在那里永久占盘，压不下来。

`context.v3` 是纯文本渲染面：它把整段窗口压成一行文字，字节无处安放，所以那里的图片
只留一行类型与大小说明。`v3` 引擎的工具结果回写、以及其余引擎与 `native`，都带真实字节。
