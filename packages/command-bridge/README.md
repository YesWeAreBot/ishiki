# Ishiki 命令桥

让 Ishiki 按当前发言人和频道介绍 Koishi 已注册的命令，并以该发言人的身份代调管理员开放的命令。默认只提供发现和帮助。支持 Koishi 4.18.11、已正常工作的 Ishiki 0.0.6 和带用户、频道记录的 Koishi 数据库。

## 配置

将包安装到运行 Ishiki 的同一 Koishi 实例，在控制台启用 `ishiki-command-bridge`。在每个要接入的 `profile.yml` 的现有 `extends` 下增加 `command-bridge`。按 Ishiki 的常规流程应用 profile，让新扩展挂载。

以下用假设已安装的掷骰和画图插件演示配置。实际填写本机 Koishi 注册的正式命令名。

```yaml
# koishi.yml，放在已启用的插件组中
ishiki-command-bridge:
  allow: [roll]
  confirm: [draw]
  deny: []
  maxCallsPerTurn: 1
```

```yaml
# profile.yml
extends:
  command-bridge:
    enable: true
    config:
      restrictCommands: true
      only: [roll, draw]
```

| 设置                                    | 作用                                                                                                      |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 插件级 `allow`                          | 可直接代调。只填写已核实无扣费、签到、点赞或管理副作用的命令                                              |
| 插件级 `confirm`                        | 可代调，每次执行前向原发言人展示命令和参数，请本人确认。与 `allow` 重复时优先确认                         |
| 插件级或 profile 级 `deny`              | 隐藏并禁止这些命令，叠加内置管理命令禁用规则                                                              |
| profile 级 `restrictCommands` 和 `only` | 开启后，只保留插件级已授权且在 `only` 中的代调项。空列表表示仅发现                                        |
| profile 级 `confirm`                    | 为已经开放的命令追加确认                                                                                  |
| `maxCallsPerTurn`                       | 每轮最多 1 或 2 次，默认 1。插件和 profile 取较小值。确认请求也占一次，同一轮相同操作只能发起一次         |
| profile 级 `notes`                      | 管理员维护的非命令功能说明，例如入群欢迎。只填写适用于该 profile 全部频道的说明，插件开关变化后需手动维护 |

## 群友看到的行为

- 问“你会什么”时，模型能看到本轮命令预览，通过 `koishi_command_list` 分页搜索全部可见命令，用 `koishi_command_help` 查看参数。每次查询读取 Koishi 的当前注册表。新装插件的命令通过权限与作用域检查后就可以介绍。
- 群友可以自己输入标记为 `manual` 的命令。只有 `execute` 和 `confirm` 可以由模型代调。新命令默认仅供介绍。
- 对需要确认的命令，桥接在原频道展示正式命令和具体参数。请求者在 60 秒内单独发送提示中的“确认执行 …”后才执行。其他账号、其他频道、超时或重复确认均无法完成这笔操作。权限和命令注册在执行时重新检查。
- 插件用 Koishi 原有方式发送文字、图片或多段结果。工具只向模型返回调用状态。如果插件本身设计为先发图再发解读，这两条都会保留。

## 代调边界

身份来自真实入站消息。标准或 willingness 引擎在接收该消息时直接唤醒的轮次可以代调。手动唤醒、定时唤醒、异步决策唤醒，以及缺少可靠来源的轮次都不提供命令工具。新的群友消息加入、路由变化或原消息撤回后，旧工具的执行权限失效。

命令、父命令、别名、权限要求、选项默认值和作用域都要通过检查。即使原发言人是管理员，桥接仍只开放权限上限为 1 的普通命令。系统与管理命令受内置禁用规则保护。工具只接受独立的纯文本位置参数，命令行选项、插值、富文本和目标实体参数需由群友自行使用。

授权面向受信任的 Koishi 插件。插件作者决定 action 内部做什么，Koishi 没有统一的扣费或副作用标签。审核 `allow` 和 `confirm` 时，也要检查插件升级后的行为和扣费账户的取值。调用期间或随后通过同一委托会话再次调用 `session.execute()` 会被阻止；依赖这种转发的命令适合保留供群友手动使用。命令之外的事件监听和自然语言关键词不会自动进入目录。

## 宿主兼容性

如果 Ishiki 0.0.6 启动时报告 `jsonSchema is not a function` 或 SDK 导出冲突，先检查 `@yesimagent/core@0.0.9` 和 `ai@7.0.137` 是否加载了不同目录下的 SDK。验证过的一组干净 npm 依赖将 `@ai-sdk/provider@4.0.26` 和 `@ai-sdk/provider-utils@5.0.58` 固定在宿主依赖树顶层，使两者使用同一份模块。打包件已按 Koishi 的 CommonJS 插件入口验证。
